Learning to code is one of the most useful things you can do as a student: the skills are in demand at home and abroad, you can learn them entirely for free, and you can practise on any laptop. This roadmap takes you from zero to your first real projects, in order.

> **Update:** Refreshed for 2026, with the free resources checked, retired tools removed, and a new section on learning to code in the age of AI assistants.

## Step 1: Pick one language (and stick with it)

The best first language is the one you will keep using. Two safe choices:

- **Python** if you are curious about data, AI, automation or science. It reads almost like English. ([python.org tutorial](https://docs.python.org/3/tutorial/))
- **JavaScript** if you want to build websites and web apps you can show people. ([MDN: JavaScript basics](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Your_first_website/Adding_interactivity))

Later you may add **Java** or **C#** (big companies, Android, games with Unity) or **Go** (cloud and back-end services), but don't start with three languages at once. The concepts (variables, loops, functions, data structures) transfer from one language to the next.

## Step 2: Set up your tools

- **Editor:** [Visual Studio Code](https://code.visualstudio.com/) is free, works on Windows, macOS and Linux, and supports every popular language through extensions. (Older tutorials mention Atom; it was discontinued in 2022.)
- **Language:** install [Python](https://www.python.org/downloads/) or [Node.js](https://nodejs.org/) (for JavaScript outside the browser).
- **Terminal:** learn a few commands (`cd`, `ls` or `dir`, running a file). MIT's free [Missing Semester](https://missing.csail.mit.edu/) is the best short introduction.

No laptop yet? You can start in the browser with free tools like [Google Colab](https://colab.research.google.com/) (Python) or [freeCodeCamp](https://www.freecodecamp.org/), which runs in your browser.

## Step 3: Learn the basics properly

Every language has the same core ideas: **variables and types, conditions (`if`), loops, functions, lists and dictionaries/objects, reading and writing files, and handling errors**.

Free places to learn them:

- **[freeCodeCamp](https://www.freecodecamp.org/)**: interactive web development and Python courses with certificates.
- **[CS50 by Harvard](https://cs50.harvard.edu/x/)**: the most famous intro to computer science, free online.
- **[The Odin Project](https://www.theodinproject.com/)**: a full, free web development path.
- Books: *Python Crash Course* (Eric Matthes) and *[Eloquent JavaScript](https://eloquentjavascript.net/)* (Marijn Haverbeke, free online).

Pick **one** course and finish it. Course-hopping is the most common way beginners stall.

## Step 4: Build projects early

Tutorials teach you to follow; projects teach you to think. Start small and make each project slightly harder than the last:

1. A tip or GPA calculator.
2. A to-do list that saves to a file.
3. A Nepali-English vocabulary quiz.
4. A personal portfolio website.
5. A small app using a public API (weather, currency rates, news headlines).

When you get stuck (you will), read the error message carefully, search it, and check [Stack Overflow](https://stackoverflow.com/) and the official documentation.

## Step 5: Data structures and algorithms (DSA)

Once you are comfortable with the basics, learn **arrays, linked lists, stacks, queues, hash maps, trees, graphs, sorting, searching and recursion**. They make your code faster and they are what most technical interviews test.

Practise on [LeetCode](https://leetcode.com/), [HackerRank](https://www.hackerrank.com/) or [Codeforces](https://codeforces.com/). Start with "easy" problems and focus on understanding patterns, not memorising answers.

## Step 6: Git and GitHub

**Git** tracks changes to your code; **GitHub** stores it online and is your public portfolio. Learn to `commit`, `push`, create branches and open pull requests. [Learn Git Branching](https://learngitbranching.js.org/) is a fun, visual way to learn. Put every project on GitHub with a short README explaining what it does.

## Step 7: Choose a direction

After a few months of basics and projects, pick a field to go deeper:

| Field | You build | Learn next |
|---|---|---|
| Web development | Websites and web apps | HTML, CSS, JavaScript, React, a back-end (Node.js or Python) |
| Mobile apps | Android/iOS apps | Kotlin, Swift, or Flutter |
| Data & AI | Analysis, ML models, AI apps | Python, NumPy, pandas, then the [AI & ML roadmap](/ai-roadmap/) |
| Back-end & cloud | APIs, databases, servers | SQL, a framework, Docker, a cloud platform |
| Cybersecurity | Securing systems | Networking, Linux, security fundamentals |

## Step 8: Learning to code in the age of AI

AI coding assistants can write a lot of code. That makes understanding code **more** valuable, not less: someone has to judge whether the code is right, secure and maintainable. Use them like a patient tutor, not a ghost-writer:

- **Do:** ask AI to explain an error, explain a piece of code line by line, or quiz you on a concept.
- **Do:** write your own solution first, then ask for a review.
- **Don't:** paste in an assignment and submit the answer. You'll pass the exercise and fail the interview.

## Step 9: Ship something and join a community

- **Deploy** your projects so others can use them: [GitHub Pages](https://pages.github.com/) hosts websites for free (this site runs on it).
- **Join communities:** your college's coding club, local meetups and hackathons, and open-source projects on GitHub.
- **Share your progress** on LinkedIn or a blog. Explaining what you learned is the best way to remember it.

## A realistic schedule

There is no perfect timeline, but a steady pace works: **an hour a day, every day**. Roughly: basics and small projects first, then DSA alongside bigger projects, then a specialisation. Consistency matters far more than speed.
